# 📋 Правила создания статей для блога YAPPIE

## 1. Структура файлов

### Расположение
```
data/blog/
├── razrabotka-saytov/          # Кластер: Разработка сайтов
│   └── nazvanie-statyi.js      # Файл статьи
├── sozdanie-saytov/            # Кластер: Создание сайтов
├── mobilnye-prilozheniya/      # Кластер: Мобильные приложения
├── veb-razrabotka/             # Кластер: Веб-разработка
└── iskusstvennyy-intellekt/    # Кластер: Искусственный интеллект
```

### Именование файлов
- **Формат**: `kebab-case.js` (строчные буквы, дефисы вместо пробелов)
- **Примеры**: 
  - ✅ `razrabotka-sayta-pod-klyuch.js`
  - ✅ `stoimost-sozdaniya-sayta.js`
  - ❌ `Разработка сайта.js`
  - ❌ `razrabotka_sayta.js`

## 2. Структура объекта статьи

```javascript
export default {
  // URL статьи (обязательно)
  slug: 'razrabotka-sayta-pod-klyuch',
  
  // Заголовок H1 (обязательно, 50-70 символов)
  title: 'Разработка сайта под ключ: полное руководство',
  
  // Описание для SEO (обязательно, 150-160 символов)
  description: 'Полное руководство по разработке сайта: этапы, сроки, стоимость в 2025 году.',
  
  // Категория для фильтра (обязательно)
  category: 'Разработка сайтов',
  
  // Кластер для группировки (обязательно, = имя папки)
  cluster: 'razrabotka-saytov',
  
  // Дата публикации (обязательно, формат YYYY-MM-DD)
  date: '2026-02-20',
  
  // Путь к изображению (опционально, null если нет)
  image: null,
  // или: image: '/blog/images/nazvanie-statyi.jpg'
  
  // HTML-контент статьи (обязательно)
  content: `
    <p>Первый абзац статьи...</p>
    
    <h2>Заголовок раздела H2</h2>
    
    <p>Текст раздела...</p>
  `
}
```

## 3. Правила заполнения полей

### slug
- Уникальный идентификатор статьи
- Используется в URL: `/blog/{slug}`
- Только строчные буквы, цифры и дефисы
- Без пробелов и спецсимволов
- Должен совпадать с именем файла (без .js)

**Примеры:**
- ✅ `razrabotka-sayta-pod-klyuch`
- ✅ `chat-boty-dlya-biznesa-2025`
- ❌ `разработка сайта`
- ❌ `razrabotka_sayta`

### title
- Главный заголовок H1 статьи
- Должен содержать ключевое слово
- Длина: 50-70 символов для SEO
- Привлекательный для клика

**Примеры:**
- ✅ `Разработка сайта под ключ: полное руководство по этапам`
- ❌ `Разработка сайта` (слишком коротко)
- ❌ `Статья про то, как мы разрабатываем сайты для клиентов...` (слишком длинно)

### description
- Описание для поисковых систем и превью
- Длина: 150-160 символов
- Должен содержать ключевое слово
- Призыв к действию желателен

**Примеры:**
- ✅ `Разбираем реальные кейсы автоматизации бизнес-процессов с помощью AI. Узнайте, какие задачи можно делегировать.`

### category
- Общая категория для фильтрации
- Должна совпадать с другими статьями кластера
- Используется в UI как ярлык

**Допустимые категории:**
- `Разработка сайтов`
- `Создание сайтов`
- `Мобильные приложения`
- `Веб-разработка`
- `Искусственный интеллект`
- `Автоматизация`
- `Чат-боты`
- `CRM`

### cluster
- Техническое поле для группировки
- Должно совпадать с именем папки
- Используется для навигации по кластерам
- Каждый кластер имеет свой цвет в интерфейсе

**Значения и цвета:**
- `razrabotka-saytov` — фиолетовый (Разработка сайтов)
- `sozdanie-saytov` — синий (Создание сайтов)
- `mobilnye-prilozheniya` — зелёный (Мобильные приложения)
- `veb-razrabotka` — оранжевый (Веб-разработка)
- `iskusstvennyy-intellekt` — розовый (Искусственный интеллект)

### date
- Дата публикации в формате ISO
- Влияет на сортировку (новые первыми)
- Используется для Schema.org разметки

**Формат:** `YYYY-MM-DD`
- ✅ `2026-02-20`
- ❌ `20.02.2026`
- ❌ `20 февраля 2026`

### image
- Путь к изображению превью (опционально)
- Размер рекомендуется 1200x630px (Open Graph)
- Форматы: .jpg, .png, .webp
- Если нет изображения: `null`

**Примеры:**
- `null`
- `/blog/images/razrabotka-sayta.jpg`
- `/images/blog/avtomatizaciya.jpg`

## 4. HTML-форматирование контента

### Базовая структура
```html
<p>Вступительный абзац...</p>

<h2>Заголовок раздела H2</h2>

<p>Текст раздела...</p>

<h3>Подзаголовок H3</h3>

<p>Ещё текст...</p>

<h2>Следующий раздел H2</h2>

<p>Текст...</p>
```

### Иерархия заголовков
- `<h1>` — НЕ используется в content (есть title)
- `<h2>` — Главные разделы статьи
- `<h3>` — Подразделы
- `<h4>` — Редко используется

**Правила:**
- Всегда начинайте с `<p>` или `<h2>`
- Не пропускайте уровни (после h2 сразу h4 — ошибка)
- Один h2 = один раздел

### Текстовые элементы

**Параграфы:**
```html
<p>Обычный текст...</p>
<p>Второй абзац...</p>
```

**Выделение:**
```html
<p>Текст с <strong>жирным выделением</strong> для важности.</p>
<p>Текст с <em>курсивом</em> для акцента.</p>
```

### Списки

**Маркированный список:**
```html
<ul>
  <li>Первый пункт</li>
  <li>Второй пункт</li>
  <li>Третий пункт</li>
</ul>
```

**Нумерованный список:**
```html
<ol>
  <li>Первый шаг</li>
  <li>Второй шаг</li>
  <li>Третий шаг</li>
</ol>
```

### Цитаты
```html
<blockquote>
  Текст цитаты. Может быть длинным, на несколько строк.
</blockquote>
```

### Таблицы

**Важно:** Все таблицы нужно оборачивать в div с классом `table-wrapper` для горизонтального скролла на мобильных устройствах:

```html
<div class="table-wrapper">
  <table>
    <thead>
      <tr>
        <th>Заголовок 1</th>
        <th>Заголовок 2</th>
        <th>Заголовок 3</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td>Данные 1</td>
        <td>Данные 2</td>
        <td>Данные 3</td>
      </tr>
      <tr>
        <td>Данные 4</td>
        <td>Данные 5</td>
        <td>Данные 6</td>
      </tr>
    </tbody>
  </table>
</div>
```

### Ссылки

**Важно:** Все внутренние ссылки должны включать baseURL `/website1/`:

```html
<!-- Внутренние ссылки на блог -->
<a href="/website1/blog">Все статьи</a>
<a href="/website1/blog/drugaya-statya">Текст ссылки</a>

<!-- Внутренние ссылки на главную -->
<a href="/website1/">На главную</a>

<!-- Внешние ссылки (обязательно target="_blank") -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">Внешняя ссылка</a>

<!-- Ссылки на источники -->
<a href="https://statista.com" target="_blank" rel="noopener noreferrer">Statista</a>
```

### Изображения внутри статьи
```html
<img src="/blog/images/illustraciya.jpg" alt="Описание изображения" />
```

### Специальные элементы

**Информационный блок:**
```html
<blockquote>
  <strong>Важно:</strong> Текст важной информации.
</blockquote>
```

**Совет:**
```html
<blockquote>
  💡 <strong>Совет:</strong> Текст совета.
</blockquote>
```

### CTA блоки (Призывы к действию)

CTA блоки — это выделенные блоки с кнопкой, которые ведут на Telegram. Используйте их в ключевых местах статьи для конверсии читателей в лиды.

**Базовый CTA блок:**
```html
<div class="cta-block">
  <p>Текст призыва к действию</p>
  <a href="https://t.me/artemselifanov" target="_blank" class="cta-button">
    Текст кнопки
    <span>→</span>
  </a>
</div>
```

**Примеры текстов для CTA:**
- "Не знаете, сколько будет стоить ваш проект?"
- "Готовы обсудить ваш проект?"
- "Нужна консультация по разработке сайта?"
- "Хотите узнать стоимость вашего проекта?"

**Примеры текстов кнопок:**
- "Получить расчёт стоимости"
- "Написать в Telegram"
- "Бесплатная консультация"
- "Обсудить проект"

**Где размещать CTA блоки:**
1. В середине статьи (после ключевого раздела или проблемы)
2. В конце статьи (финальный призыв к действию)

**Важно:**
- Размещайте ровно 2 CTA блока: один в середине, один в конце
- Текст должен быть конкретным и полезным
- Кнопка должна обещать выгоду (бесплатно, расчёт, консультация)

## 4.1. Навигация между статьями

В конце каждой статьи добавляйте блок навигации для перелинковки:

**Важно:** Используйте полный путь с `/website1/blog/`:

**Первая статья в списке:**
```html
<div class="article-nav">
<p><strong>Читать далее:</strong> <a href="/website1/blog/sleduyushchaya-statya">Название следующей статьи →</a></p>
</div>
```

**Статьи в середине списка:**
```html
<div class="article-nav">
<p><strong>Читать далее:</strong> <a href="/website1/blog/sleduyushchaya-statya">Название следующей статьи →</a></p>
<p><strong>Назад:</strong> <a href="/website1/blog/predydushchaya-statya">← Название предыдущей статьи</a></p>
</div>
```

**Последняя статья в списке:**
```html
<div class="article-nav">
<p><strong>Назад:</strong> <a href="/blog/predydushchaya-statya">← Название предыдущей статьи</a></p>
</div>
```

**Правила:**
- Навигация размещается после источников, перед закрывающим тегом content
- Ссылки ведут на полный slug статьи
- Формат: «Читать далее:» → для следующей, «Назад:» ← для предыдущей
- Порядок статей определяется массивом в `data/blog.js`

## 5. SEO-оптимизация

### Ключевые слова
- Используйте ключевое слово в title, description, первом абзаце
- Разбавляйте синонимами ("разработка сайта", "создание сайта", "веб-разработка")
- Плотность ключевых слов: 1-2%

### ЧПУ (человекопонятные URL)
- slug должен содержать ключевое слово
- Короткий и описательный

### Внутренняя перелинковка
- Добавляйте ссылки на другие статьи блога
- Используйте релевантные анкоры

### Мета-данные
- Уникальный title и description для каждой статьи
- Не дублируйте с другими статьями

### Структура контента
- Используйте заголовки с ключевыми словами
- Добавляйте маркированные списки (Google любит)
- Статья должна быть минимум 2000-3000 символов

## 7. Чек-лист перед сохранением

- [ ] slug совпадает с именем файла
- [ ] title 50-70 символов
- [ ] description 150-160 символов
- [ ] category и cluster заполнены
- [ ] date в формате YYYY-MM-DD
- [ ] content начинается с `<p>` или `<h2>`
- [ ] Иерархия заголовков соблюдена (h2 → h3)
- [ ] Все открывающие теги имеют закрывающие
- [ ] **Таблицы обёрнуты в `<div class="table-wrapper">`**
- [ ] **Внутренние ссылки с `/website1/` (например: `/website1/blog/statya`)**
- [ ] Внешние ссылки с `target="_blank" rel="noopener noreferrer"`
- [ ] Навигация между статьями добавлена (article-nav)
- [ ] Нет опечаток в ключевых словах
- [ ] Статья импортирована в `data/blog.js`
- [ ] Сборка проходит без ошибок (`npm run generate`)

## 11. Пошаговый процесс создания новой статьи (на примере Claude AI для бизнеса)

Этот раздел описывает полный цикл создания статьи от идеи до публикации на реальном примере.

### Шаг 1: Определение темы и кластера

**Пример:** Статья "Claude AI для бизнеса"
- **Тема:** Обзор Claude от Anthropic для бизнес-аудитории
- **Кластер:** `iskusstvennyy-intellekt` (папка `/data/blog/iskusstvennyy-intellekt/`)
- **Ключевое слово:** "claude для бизнеса", "anthropic claude"

### Шаг 2: Создание файла статьи

```bash
# Перейдите в папку кластера
cd data/blog/iskusstvennyy-intellekt/

# Создайте файл с именем в kebab-case
touch claude-dlya-biznesa.js
```

**Важно:** Имя файла должно совпадать с будущим slug!

### Шаг 3: Заполнение базовых полей

Откройте файл и добавьте структуру:

```javascript
export default {
  slug: 'claude-dlya-biznesa',
  title: 'Claude AI для бизнеса: возможности, модели и сценарии применения в 2026 году',
  description: 'Полный обзор Claude от Anthropic: модели Opus и Sonnet, тарифы, сравнение с ChatGPT. Как внедрить AI в бизнес-процессы.',
  category: 'Искусственный интеллект',
  cluster: 'iskusstvennyy-intellekt',
  date: '2026-04-16',
  image: null,
  content: ``
}
```

**Проверка:**
- ✅ slug = имя файла (без .js)
- ✅ title = 50-70 символов, содержит ключевое слово
- ✅ description = 150-160 символов, есть призыв к действию
- ✅ category = одна из допустимых (см. раздел 3)
- ✅ cluster = имя папки
- ✅ date = формат YYYY-MM-DD

### Шаг 4: Написание контента

**Структура статьи:**

```javascript
content: `
```

## 12. Часто задаваемые вопросы

**Q: Какой slug выбрать?**
A: Используйте транслитерацию ключевого слова в kebab-case. Пример: "Claude для бизнеса" → `claude-dlya-biznesa`

**Q: Сколько CTA блоков нужно?**
A: Ровно 2: один в середине статьи (после ключевого раздела), один в конце (перед навигацией).

**Q: Как определить предыдущую и следующую статью?**
A: Смотрите массив `blogPosts` в `data/blog.js`. Статья выше в массиве = предыдущая, ниже = следующая.

**Q: Что делать если статья не отображается?**
A: Проверьте:
1. Импорт в `data/blog.js`
2. Правильность экспорта (`export default`)
3. Отсутствие синтаксических ошибок в JS
4. Запустите `npm run generate` для проверки

**Q: Можно ли использовать Markdown в контенте?**
A: Нет, только чистый HTML. Markdown не поддерживается.
