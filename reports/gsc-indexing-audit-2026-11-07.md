# Аудит индексации Google Search Console — 7 ноября 2026

## Вывод

Основная техническая причина категории «Страница с переадресацией» установлена: GitHub Pages отдаёт статические маршруты в варианте с завершающим слэшем, тогда как прежняя sitemap публиковала 365 URL без него. Каждый такой URL выполнял один `301` на эквивалентный URL со слэшем.

Это не проблема `http`/`https`, `www`/non-`www` и не цепочки редиректов. Это единая системная ошибка формата URL в генераторе sitemap, дополненная каноническими тегами без слэша. В sitemap также находился отсутствующий URL `/offline`, который возвращал `404`.

Исправление подготовлено локально:

- `scripts/generate-sitemap.mjs` публикует все маршруты, кроме главной, с завершающим `/`;
- `/offline` исключён из sitemap;
- canonical для блога, кластеров, базы знаний и основных страниц приведён к конечному URL со слэшем.

Изменения ещё не опубликованы на проде. До деплоя живой сайт продолжает отдавать старую sitemap.

## Динамика

- 10 августа: 190 проиндексированных URL.
- 17 октября: 141 URL, снижение на 49 URL или 25,8%.
- 20 октября: «Не проиндексировано» изменилось с 418 до 245 URL, то есть минус 173 URL за один день; пул проиндексированных остался равным 141.

Вывод по 20 октября: это не похоже на изменение `robots.txt` или массовое добавление `noindex`. В истории git за октябрь отсутствуют изменения `robots.txt`, генератора sitemap и route rules. Кроме того, при блокировке обхода обычно меняется состав исключённых причин, но резкое исчезновение 173 URL при неизменном числе индексируемых сильнее похоже на пересчёт/очистку данных GSC или исчезновение одной категории исключений. Точный список исчезнувших URL нельзя восстановить из текущей агрегированной выгрузки.

## Контент: 75 URL «Просканирована, но пока не проиндексирована»

Сводный экспорт не содержит сам список 75 URL, поэтому нельзя честно выбрать 10 перспективных страниц или проверить их title, description, canonical и внутренние ссылки. Любой такой список был бы предположением, а не аудитом.

Для продолжения нужен экспорт URL из карточки каждой причины в GSC:

1. Открыть «Страница просканирована, но пока не проиндексирована».
2. Экспортировать таблицу примеров URL в CSV/Google Sheets.
3. Аналогично экспортировать таблицу «Страница с переадресацией».
4. Если GSC не показывает все URL, выгрузить их через Search Console API или прислать скрин/CSV таблицы с URL, датой последнего сканирования и источником обнаружения.

После получения списка для каждого URL нужно проверить:

- итоговый `200`, self-canonical со слэшем, `index, follow`;
- уникальность title/description и достаточность основного текста;
- число входящих внутренних ссылок с индексируемых URL;
- вложенность от главной и наличие в актуальной sitemap;
- пересечение семантики с более сильными материалами, чтобы исключить каннибализацию.

Приоритет для реанимации: сначала URL с уникальным содержанием, self-canonical, `200`, местом в sitemap и 0–1 входящей ссылкой; затем добавить 3–5 контекстных ссылок из хабов, статей кластера и связанных материалов. Нельзя выбрать именно 10 страниц до получения их списка из GSC.
